## 1. Вступ та методологія

Цей документ описує модель загроз безпеки для мобільного застосунку **Writer Editor** (React Native / Expo). Аналіз загроз виконано за методологією **STRIDE**, яка розглядає шість основних категорій ризиків для мобільного клієнтського додатку з локальним збереженням даних.

Моделювання загроз проводиться на етапі проектування з метою розробки контрзаходів для захисту авторського контенту (книг, розділів), забезпечення цілісності БД та стабільності роботи застосунку.

---

## 2. Активи системи (Assets)

1. **База даних `writer-editor.db`:** Локальна базі даних SQLite, яка містить тексти книг, розділів та статистику.
2. **Текстовий контент розділів:** Авторські матеріали користувача.
3. **Файли експорту (`.docx`, `.txt`):** Тимчасові файли, згенеровані у кеші для поширення.
4. **Обкладинки книг:** Малюнки, обрані користувачем з галереї.

---

## 3. Аналіз загроз за категоріями STRIDE

### 3.1 Spoofing (Підміна)
- **Загроза S-1 (Підміна обкладинки):** Спроба передачі невалідного URI малюнка.
  - *Контрзахід:* Використання стандартного `expo-image-picker`, який повертає безпечний локальний URI, та обробка помилок завантаження в `Image`.
- **Загроза S-2 (Supply Chain Attack):** Підміна підлеглих npm-пакунків у `node_modules`.
  - *Контрзахід:* Фіксація версій у `package-lock.json` та проведення аудиту через `npm audit`.

### 3.2 Tampering (Фабрикація / Модифікація даних)
- **Загроза T-1 (XML-ін'єкція у файли DOCX):** Введення користувачем спецсимволів XML (`<`, `>`, `&`, `"`, `'`), що може пошкодити структуру OpenXML файлу Word.
  - *Контрзахід:* Обов'язкове екранування всіх текстових полів через функцію `escapeXml()` перед генерацією `.docx`.
- **Загроза T-2 (SQL-ін'єкція):** Введення SQL-конструкцій у полі пошуку чи назвах книг.
  - *Контрзахід:* Використання параметризованих SQL-запитів із плейсхолдерами `?` у всіх функціях `src/database/client.js`.

### 3.3 Repudiation (Відмова від дій / Випадкове видалення)
- **Загроза R-1 (Випадкове видалення матеріалів):** Ненавмисне знищення книги чи розділу користувачем.
  - *Контрзахід:* Обов'язкове підтвердження деструктивних дій у модальних вікнах `ConfirmActionModal`.

### 3.4 Information Disclosure (Витік інформації)
- **Загроза I-1 (Витік тимчасових файлів експорту):** Залишки `.docx` чи `.txt` файлів у `cacheDirectory`.
  - *Контрзахід:* Використання внутрішніх каталогів пісочниці додатку та перезапис файлів при повторному експорті.
- **Загроза I-2 (Витік винятків у консоль):** Виведення повних системних стек-трейсів у консоль.
  - *Контрзахід:* Обробка помилок через допоміжну утиліту `serializeError()`, яка обмежує виведення лише повідомленням про помилку.

### 3.5 Denial of Service (Відмова в обслуговуванні — DoS)
- **Загроза D-1 (Переповнення пам'яті в WebView):** Введення надвеликих обсягів тексту в Rich Text редактор.
  - *Контрзахід:* Автозбереження за допомогою Debounce (затримка 500 мс) та використання оптимізованого очищувача HTML.
- **Загроза D-2 (Блокування БД SQLite):** Часті паралельні виклики SQL `UPDATE`.
  - *Контрзахід:* Налаштування режиму `PRAGMA journal_mode = WAL;` при ініціалізації бази.

### 3.6 Elevation of Privilege (Підвищення привілеїв)
- **Загроза E-1 (Path Traversal при збереженні файлу):** Спроба використання символів `../` у назві книги для запису файлу за межі дозволеного каталогу.
  - *Контрзахід:* Санітизація назви файла через `sanitizeFileName()`, яка видаляє символи `/`, `\`, `:` тощо.

## 4. Оцінка ризиків (Threat Risk Matrix)

| ID | Категорія | Загроза | Рівень ризику | Статус нейтралізації |
|---|---|---|---|---|
| **TH-T1** | Tampering | XML-ін'єкція у DOCX | **Високий** | Нейтралізовано (`escapeXml`) |
| **TH-T2** | Tampering | SQL-ін'єкція | **Високий** | Нейтралізовано (Параметричні SQL) |
| **TH-E1** | Elevation of Privilege | Path Traversal у назві файла | **Високий** | Нейтралізовано (`sanitizeFileName`) |
| **TH-I1** | Info Disclosure | Залишки файлів у кеші | **Середній** | Частково (Кеш пісочниці ОС) |
| **TH-D1** | DoS | Перевантаження WebView | **Низький** | Нейтралізовано (Debounce 500ms) |
| **TH-R1** | Repudiation | Випадкове видалення книги | **Середній** | Нейтралізовано (Модальні вікна) |

## 5. Сводна матриця контрзаходів

1. **Параметризація SQL-запитів:** Усі операції з `expo-sqlite` виконуються виключно через масив параметрів `?`.
2. **Екранування XML:** Весь текст перед збіркою в `.docx` архів обробляється функцією `escapeXml()`.
3. **Очищення імен файлів:** Усі назви файлів для експорту проганяються через `sanitizeFileName()`.
4. **Підтвердження операцій:** Усі деструктивні дії вимагають підтвердження користувача у `ConfirmActionModal`.
