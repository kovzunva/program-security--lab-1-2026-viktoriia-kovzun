## 1. Вступ та системний контекст

Цей документ містить архітектурний опис мобільного застосунку **Writer Editor**, розроблений відповідно до стандарту **ISO/IEC/IEEE 42010:2022**. Документ визначає ключові архітектурні точки зору (Viewpoints), розбиття системи на шари, взаємодію компонентів та межі довіри (Trust Boundaries).

Застосунок проектується на базі кросплатформеного фреймворку React Native / Expo і працює за принципом **Client-Side Only / Offline-First**: усі дані обробляються та зберігаються локально на мобільному пристрої.

---

## 2. Архітектурні точки зору (Architectural Viewpoints)

### 2.1 Context Viewpoint (Контекстна точка зору)

Контекстна точка зору описує взаємодію застосунку з користувачем та нативними сервісами операційної системи мобільного пристрою:

- **Користувач / Автор:** Взаємодіє з мобільним додатоком через графічний інтерфейс користувача (UI).
- **Writer Editor App:** Виконує бізнес-логіку, підраховує статистику слів, обробляє форматований текст.
- **Локальна БД SQLite (`writer-editor.db`):** Зберігає книги, розділи та сесії написання через параметризовані SQL-запити.
- **Файлова система ОС (Expo FileSystem):** Використовується для тимчасового збереження експортованих `.docx` та `.txt` файлів у каталогах `documentDirectory` або `cacheDirectory`.
- **Галерея зображень (Expo ImagePicker):** Нативний модуль для вибору обкладинки книги.
- **Системний діалог поширення (Expo Sharing):** Нативний шар ОС для передачі файлів в інші додатки (месенджери, пошта, хмарні диски).

---

### 2.2 Component & Layered Viewpoint (Пошарова компонента точка зору)

Систему сплановано у вигляді 5 ізольованих шарів:

1. **Presentation Layer (Шар інтерфейсу користувача):**
   - **Screens:** `LibraryScreen`, `BookDetailsScreen`, `BookMetaFormScreen`, `BookChaptersScreen`, `EditorScreen`, `BookStatsScreen`, `SettingsScreen`, `InfoScreen`.
   - **Components:** `ConfirmActionModal`, `ExportFormatModal`, `PopupMenu`, `StatBadge`, `Toast`.
   - **Theme & Localization:** `ThemeProvider`, `LocalizationProvider`.
2. **Navigation Layer (Шар навігації):**
   - `AppNavigator` на базі React Navigation Stack для управління переходами між екранами.
3. **Business Logic & Services Layer (Сервісний шар бізнес-логіки):**
   - `bookExport.js` — генерація та експорт файлів `.docx` (через `jszip`) та `.txt`.
   - Утиліти обробки тексту: `richHtmlToPlainText`, `escapeXml`, `sanitizeFileName`, `countWords`.
4. **Data Access Layer (Шар доступу до даних — DAL):**
   - `src/database/client.js` — модуль ініціалізації SQLite, створення схем таблиць та виконання параметризованих запитів.
5. **Native OS & Storage Layer (Шар нативних модулів ОС):**
   - `expo-sqlite`, `expo-file-system`, `expo-sharing`, `expo-image-picker`.

---

### 2.3 Security & Trust Boundaries Viewpoint (Межі довіри та безпеки)

В архітектурі системи виділяються наступні межі довіри (Trust Boundaries):

1. **TB-1: Untrusted User Input Boundary (Межа вводу користувача):**
   - Межа між користувачем та UI-компонентами. Всі введені дані (назва книги, текст) вважаються потенційно некоректними і вимагають валідації та санітизації.
2. **TB-2: WebView / Editor Boundary (Межа візуального редактора):**
   - Межа між JS-рушієм додатка та вбудованим WebView компонента `RichEditor`. HTML-текст при отриманні з WebView проганяється через очищення.
3. **TB-3: App Sandbox Boundary (Межа пісочниці додатку):**
   - Внутрішнє ізольоване середовище ОС iOS/Android, що обмежує доступ сторонніх додатків до файлу `writer-editor.db`.
4. **TB-4: External OS Share Boundary (Межа передачі файлів у зовнішні додатки):**
   - Межа при передачі файлів через системний `Share Sheet`. Тимчасові файли очищаються з кешу при повторному експорті.

## 3. Опис потоку даних при ключових операціях

### 3.1 Потік автозбереження тексту розділу:
1. Користувач вводить текст у `EditorScreen` -> спрацьовує Debounce-таймер (500 мс).
2. UI викликає метод `updateChapterContent()` з Data Access Layer (`client.js`).
3. DAL виконує параметризований SQL `UPDATE` в базі SQLite.
4. База даних повертає підтвердження -> UI оновлює статус на "Збережено".

### 3.2 Потік експорту книги в DOCX:
1. Користувач натискає "Експорт в DOCX" -> UI викликає `exportBook()` із сервісного шару (`bookExport.js`).
2. Сервіс очищає назву файлу через `sanitizeFileName()` та екранує текст через `escapeXml()`.
3. За допомогою `jszip` у пам'яті будується архів OpenXML `.docx`.
4. Файл записується на диск через `expo-file-system` та відкривається системний діалог `expo-sharing`.

## 4. Архітектурні рішення (ADR Summary)

- **ADR-1 (SQLite замість AsyncStorage):** Обрано `expo-sqlite` для підтримки реляційних зв'язків між книгами та розділами, автоматичного підрахунку статистики та каскадного видалення.
- **ADR-2 (Генерація DOCX на клієнті через JSZip):** Експорт реалізується прямо на пристрої без використання зовнішніх серверів конвертації.
- **ADR-3 (Debounced Autosave):** Текст автозберігається з затримкою 500 мс для оптимізації кількості записів на диск.
