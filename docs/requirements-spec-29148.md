## 1. Вступ та скоуп системи

Цей документ містить специфікацію вимог до розробки мобільного застосунку **Writer Editor** (на базі React Native та Expo). Застосунок призначений для створення, редагування, аналізу статистики та експорту текстових книг і розділів на мобільних пристроях.

Система розробляється за концепцією **Offline-First**: усі дані зберігаються локально у реляційній базі даних SQLite (`writer-editor.db`) без обов'язкового підключення до Інтернету.

## 3. Функціональні вимоги (Functional Requirements — FR)

### 3.1 Управління бібліотекою книг
- **FR-1.1:** Система повинна дозволяти створення книги з вказанням назви, опису, жанру та обкладинки.
- **FR-1.2:** Система повинна відображати список збережених книг із кількістю розділів та слів.
- **FR-1.3:** Система повинна забезпечувати миттєвий пошук книг за назвою.
- **FR-1.4:** Система повинна дозволяти редагування метаданих книги та її видалення з підтвердженням.

### 3.2 Редагування розділів
- **FR-2.1:** Система повинна дозволяти додавання, перейменування та видалення розділів у книзі.
- **FR-2.2:** Система повинна надавати візуальний Rich Text редактор з панеллю форматування (жирний, курсив, закреслений).
- **FR-2.3:** Система повинна автоматично зберігати текст розділу (через 500 мс після зупинки введення або при втраті фокусу).

### 3.3 Експорт файлів
- **FR-3.1:** Система повинна підтримувати експорт всієї книги у формати `.docx` та `.txt`.
- **FR-3.2:** Після генерації файлу система повинна викликати системний діалог поширення ОС (`expo-sharing`).

### 3.4 Локалізація та теми
- **FR-4.1:** Підтримка мов інтерфейсу: українська (`uk`), англійська (`en`), німецька (`de`).
- **FR-4.2:** Підтримка тем: світла (`light`), темна (`dark`), системна (`system`).

### 3.5 Локальна автентифікація та авторизація
- **FR-5.1 (Майстер-PIN):** Можливість увімкнення/вимкнення 4-значного майстер-PIN для захисту входу в застосунок.
- **FR-5.2 (Безпечне хешування):** Збереження PIN-коду у вигляді соленого bcrypt-хешу (`bcryptjs`, cost 10) в таблиці `auth_settings` без відкритого тексту.
- **FR-5.3 (Захист від брутфорсу / Rate Limiting):** Фіксація невдалих спроб введення PIN. Після 5 помилкових спроб підбору вхід блокується на 45 секунд з відображенням таймера.
- **FR-5.4 (Біометрична автентифікація):** Опціональна автентифікація за допомогою Touch ID / Face ID через `expo-local-authentication`.
- **FR-5.5 (Атрибутивний контроль доступу ABAC):** Прапор `is_locked` у таблиці `chapters` для позначення окремих розділів як захищених із вимогою підтвердження PIN перед доступом.
- **FR-5.6 (Автоблокування сесії):** Автоматичне скидання авторизованого стану при згортанні застосунку в фоновий режим (`AppState`).
- **FR-5.7 (Криптографічний захист рукописів):** Прозоре автентифіковане шифрування вмісту розділів книг (`chapters.body`) при збереженні в локальній базі даних SQLite та автоматичне розшифрування при читанні/редагуванні.
- **FR-5.8 (Контроль цілісності AEAD):** Обов'язкова перевірка мітки автентичності (Auth Tag) при дешифруванні з перехопленням спроб модифікації та генерацією винятку `"Integrity check failed: data tampered"`.
- **FR-5.9 (Управління ключами):** Генерація 256-бітного симетричного ключа CSPRNG або його деривація через PBKDF2 (HMAC-SHA256, 10 000+ ітерацій) на основі криптографічної солі та PIN-коду автора зі збереженням у захищеному сховищі.

## 4. Нефункціональні вимоги з фокусом на тріаду CIA (NFR)

### 4.1 Конфіденційність (Confidentiality — C)
- **NFR-C-1 (Ізольоване сховище):** База даних SQLite та обкладинки книг мають зберігатися у внутрішній пісочниці додатка (Internal Sandbox).
- **NFR-C-2 (Відсутність витоку даних):** Застосунок не повинен надсилати матеріали книг на сторонні аналітичні чи хмарні сервіси.
- **NFR-C-3 (Очищення кешу):** Тимчасові файли експорту в `cacheDirectory` мають перезаписуватися або очищатися.
- **NFR-C-4 (Data-at-Rest Encryption):** Усі чутливі авторські тексти розділів у стані спокою (Data-at-Rest) у файлі `writer-editor.db` повинні бути зашифровані за стандартом AES-256 в режимі автентифікованого шифрування (AEAD: AES-256-GCM). Метадані книг (назва, жанр, кількість слів) зберігаються відкритими для швидкого пошуку та індексації в бібліотеці.
- **NFR-C-5 (Nonce Reuse Prohibition — Заборона повторного використання IV):** Для кожної операції шифрування/збереження обов'язково генерується новий унікальний 96-бітний початковий вектор (IV / Nonce) за допомогою криптографічного генератора псевдовипадкових чисел (CSPRNG). Повторне використання Nonce з тим самим ключем суворо заборонено, що унеможливлює атаки відновлення гами (Known-Plaintext Attack).

### 4.2 Цілісність (Integrity — I)
- **NFR-I-1 (Реляційна цілісність):** Використання `PRAGMA foreign_keys = ON;`. Видалення книги має каскадно видаляти всі її розділи (`ON DELETE CASCADE`).
- **NFR-I-2 (Захист від SQL Injection):** Усі виклики до SQLite повинні використовувати лише параметризовані запити з `?`.
- **NFR-I-3 (Екранування XML/HTML):** При формуванні `.docx` файл проганяється через `escapeXml()`, щоб унеможливити пошкодження документу.
- **NFR-I-4 (Безпека імен файлів):** Ім'я файла для експорту очищається від спецсимволів через `sanitizeFileName()`.
- **NFR-I-5 (Криптографічний контроль цілісності AEAD):** Кожен зашифрований текст супроводжується 128-бітною міткою автентичності (Auth Tag). Будь-яка несанкціонована зміна бітів шифротексту, IV або тегу повинна викликати помилку `Integrity check failed: data tampered` та блокувати відображення фальсифікованого тексту в інтерфейсі.

### 4.3 Доступність (Availability — A)
- **NFR-A-1 (Offline-First):** 100% функціоналу створення, редагування та експорту працює без підключення до Інтернету.
- **NFR-A-2 (Стійкість автозбереження):** При помилці запису в базу додаток відображає статус помилки без раптового вильоту.
- **NFR-A-3 (Адаптивність UI):** Інтерфейс має коректно адаптуватися до альбомної та портретної орієнтації екрана.

## 5. Матриця верифікації вимог (Verification Matrix)

| ID Вимоги | Метод верифікації | Процедура перевірки |
|---|---|---|
| **FR-1.1 - FR-1.4** | Тестування UI | Ручне створення/редагування книги, перевірка результату в списку. |
| **FR-2.1 - FR-2.3** | Функціональне тестування | Введення тексту в Rich Editor, перевірка автозбереження. |
| **FR-3.1 - FR-3.2** | Інтеграційне тестування | Експорт у `.docx` та `.txt`, відкриття згенерованих файлів у MS Word. |
| **FR-5.1 - FR-5.6** | Тестування безпеки | Перевірка блокування після 5 спроб PIN, хешування bcrypt, ABAC. |
| **FR-5.7 - FR-5.9** | Криптографічне тестування | Верифікація AES-256-GCM, PBKDF2-деривації, перевірка унікальності IV. |
| **NFR-C-1 - NFR-C-3** | Аудит безпеки | Перевірка відсутності мережевих запитів під час роботи додатку. |
| **NFR-C-4 - NFR-C-5** | Криптографічний аудит | Перевірка відсутності відкритого тексту в SQLite (`writer-editor.db`) та верифікація випадковості IV для повторних збережень. |
| **NFR-I-1 - NFR-I-4** | Код-рев'ю | Аудит SQL-запитів на наявність параметризації та перевірка `escapeXml()`. |
| **NFR-I-5** | Атака на цілісність (Fault Injection) | Модифікація байтів шифротексту/тегу в БД, перевірка виклику винятку `"Integrity check failed: data tampered"`. |
| **NFR-A-1 - NFR-A-3** | Ручне тестування | Перевірка роботи в режимі "у літаку" та при повороті екрана. |
